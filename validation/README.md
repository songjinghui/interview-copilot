# validation/ — 找岗、代投与反馈回收验证

本目录存放用于验证「求职助手」核心路径是否可通的脚本与配置。

2026-11-03 文档更新：已纳入用户提供的[岗位获取能力说明](../docs/job-search-capability.md)。本页同时区分另一 Agent 的实测记录与本目录脚本结果；产品范围见 [VISION v0.10](../VISION.md)，后续接入方案见[岗位与 JD 获取方案](../docs/jd-acquisition-strategy.md)。

## 文件说明

| 文件 | 用途 |
|------|------|
| `targets.yaml` | 首批企业已确定为阿里、腾讯、美团；其余企业、关键词和反馈渠道仅为未验证候选。 |
| `probe.py` | 默认只读 GET 探测；可选美团公开列表和详情查询，记录原始证据并核对岗位编号、职责和要求。 |
| `local_probe.py` | 检查本机是否具备本地语音转写的基础依赖（不下载模型、不处理音频）。 |
| `requirements.txt` | 运行上述脚本所需的 Python 依赖。 |
| `tests/` | 页面误判、失败状态、限定公司范围及美团列表到详情的自动化测试；全部使用隔离样本，不访问网络。 |
| `results/primary-2026-11-03/` | 首批三家企业的页面连通性结果；根目录旧报告仅为此前连通性记录。 |
| `results/public-job-2026-11-03/` | 美团公开岗位样本、原始查询证据与该轮判断；不涵盖另一 Agent 后补的找岗验证。 |

## 运行方式

在项目根目录执行：

```powershell
# 1. 如环境缺少依赖，安装本目录声明的依赖
python -m pip install -r validation/requirements.txt

# 2. 运行项目当前完整自动化测试套件
python -X utf8 -m unittest discover -s validation/tests -p 'test_*.py' -v

# 3. 仅探测已确认的首批企业，另存本轮结果
python -X utf8 validation/probe.py --companies 阿里巴巴 腾讯 美团 --skip-platforms --output-dir validation/results/primary-2026-11-03

# 4. 验证美团公开列表到一个岗位详情；两个 POST 都是读取查询，不提交申请
python -X utf8 validation/probe.py --companies 美团 --skip-platforms --meituan-job-sample --output-dir validation/results/public-job-2026-11-03

# 5. 如需另做本地转写环境清点（不等于转写效果验证）
python -X utf8 validation/local_probe.py
```

`--config` 可指定另一份目标 YAML；不传 `--companies` 时会探测配置中的全部企业。不传 `--skip-platforms` 时还会探测配置中的 BOSS 和猎聘样本。默认输出目录为 `validation/results`，使用 `--output-dir` 可以保留不同轮次的证据。

`--meituan-job-sample` 需要所选公司包含美团；每次只读列表第一页的一个岗位，再读取该岗位的详情，不重试、不翻页、不带登录凭据。接口及参数来自本轮官网公开脚本，未经长期稳定性验证。当前样本不使用个人目标筛选，不代表用户要投递该岗位。

## 重要原则

1. **不登录、不投递、不读取隐私数据**
   - `probe.py` 只访问公开页面及可选的岗位查询接口，不提交简历、不登录账号、不读取站内消息或邮件。
   - 真实代投、消息同步、邮件读取等能力需要用户在受控环境下单独授权验证。

2. **公开页面可达 ≠ 可自动获取完整 JD / 可代投**
   - 很多页面需要执行 JavaScript、登录或处理反爬/风控才能拿到完整岗位信息。
   - 投递还涉及表单、文件上传、验证码、回执核验，不在本脚本范围内。

3. **按已确认样本验证**
   - 用户已指定阿里、腾讯、美团，无需重新提交首批公司名单。
   - 本脚本配置中的候选地址、岗位关键词和反馈渠道不代表用户偏好或能力已验证；其他 Agent 的证据按下方来源表单独引用。
   - 阿里当前 `job_search` 与首页相同，只代表入口验证，尚未定位具体业务板块的搜索页。

## 当前已验证与未验证的边界

| 能力 | 本脚本能回答 | 本脚本不能回答 |
|------|--------------|----------------|
| 找岗 | 页面状态；可选美团样本中列表与详情编号一致、职责和要求原文存在，保留完整响应 | 按用户条件的匹配效果、搜索覆盖率、持续自动化能力、岗位仍可投递 |
| 代投 | 无（不执行投递） | 是否能登录、是否能提交表单、是否能拿到回执 |
| 反馈回收 | 列出常见反馈入口 | 是否能读取站内消息/邮件/短信 |
| 本地转写 | Python 环境、可选依赖是否存在 | 转写准确率、处理速度、内存占用、录音场景兼容性 |

## 综合记录与下一步

本地首轮三个企业入口均返回 HTTP 200，但取得的 HTML 没有岗位正文；后续美团公开查询已取得一个列表岗位及对应的职责和要求原文。机器证据见 [岗位样本验证报告](results/public-job-2026-11-03/ASSESSMENT.md)，历史页面结果见 [首轮判断](results/primary-2026-11-03/ASSESSMENT.md)。新增能力说明提供另一组获取环境下的证据，不能继续把腾讯整体写成“只确认入口可达”。

| 来源 | 新增或已有证据 | 本目录脚本覆盖情况 |
|---|---|---|
| 猎聘 | 能力说明记录搜索取得 42 个岗位，列表 HTML 与详情 JD 路径可用，部分详情受登录限制 | 尚未将该 Agent 的解析与详情路径固化为项目脚本 |
| 腾讯 | 能力说明记录渲染后至少 9 个社招岗位及 JD | 本地脚本只做普通 HTTP 探测，不包含渲染能力；空壳与另一 Agent 的成功记录不矛盾 |
| 美团 | 本地脚本取得一个列表岗位及对应职责、要求原文 | `--meituan-job-sample` 可复现样本读取，条件匹配和长期稳定性待验证 |
| BOSS | 能力说明记录搜索发现或用户提供的具体详情链接可读 | 单岗读取尚未固化，列表搜索未跑通；不推定所有详情链接可读 |
| 阿里 | 本地集团招聘入口可达 | 实际列表与完整 JD 未取得 |
| 字节 | 能力说明记录结构与搜索线索 | 完整岗位路径待验证，仅作为扩展候选 |

表中 42 个、至少 9 个为能力说明记录的当次搜索量，不是当前覆盖量或本脚本测试数据。本次仅同步文档，没有重跑这些渠道，也没有修改历史 JSON 响应。

页面的 `ok` 仅代表 HTTP 200，页面的 `job_content_status` 仍为未验证。独立的 `job_sample.status = jd_sample_obtained` 表示该样本的职责和要求已取得；不代表匹配用户目标、可以投递或反馈可读。`application_status`、`feedback_status` 仍为 `not_tested`，冷却期为 `unknown`。

1. 将猎聘列表与详情、腾讯已取得成功证据的渲染路径固化到项目；复用美团样本验证实际目标筛选、更新和更多样本。补充 BOSS 单岗读取，并继续验证阿里真实岗位入口。浏览器环境需在接入时检查，上一轮本机无连接不代表其他 Agent 无法渲染。搜索摘要不能代替实际 JD。
2. 在用户授权的账号或正式测试入口中查看申请表单与回执机制；有实际岗位和材料授权后，才执行真实提交。个人招聘账号未接入时，代投继续标为未验证。
3. 用户选定实际反馈入口后，分别验证消息取得、岗位关联和去重，不把同步失败或未读到消息当成招聘方未回复。
4. 本地转写另用授权样本验证性能；环境中是否安装依赖不能代替录音与转写实测。

页面探测先新增 9 项测试，旧脚本因缺少内容分类、证据字段、公司选择或误用脚本关键词而失败；修正后通过。随后美团样本先新增 8 项测试，旧脚本因未执行样本读取而失败；实现后当前完整测试套件 **17 项通过**。此结论只适用于验证脚本，不代表产品功能或真实代投通过。
