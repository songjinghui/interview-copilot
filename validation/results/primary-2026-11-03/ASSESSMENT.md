# 阿里、腾讯、美团首轮只读验证

日期：2026-11-03。机器记录：[JSON](probe_report.json)、[可读报告](probe_report.md)。

本页保留首轮页面 GET 的结论。**后续美团已取得实际岗位职责和要求**，该轮判断见 [公开岗位样本验证](../public-job-2026-11-03/ASSESSMENT.md)。下文“未验证”指首轮范围。

用户随后提供另一 Agent 的猎聘、腾讯和 BOSS 验证记录，综合状态见[验证目录说明](../../README.md)。本页的空壳观察不否定其他获取环境下取得的岗位内容。

本轮验证的是未登录状态下的公开页面 GET，不提交表单，不发送简历，不读取私人消息。

报告记录本轮时间，以及每次请求的耗时、原地址、最终地址、状态码、正文大小、可见文字数量、脚本数量和 SHA-256。三家当前取得的静态正文字符数均为 0；这是本次请求的观察，不证明平台没有岗位，也不证明无法接入。

补充观察：从腾讯首页 HTML 发现的 `vendor/config.js` 和 `p_zh-cn_home.build.js` 两个 CDN 资源，本次直接 GET 均返回 403；没有继续尝试规避限制。这不构成对全部公开数据接口或浏览器访问能力的结论。

## 尚未验证

- **完整 JD 与找岗**：本轮没有取得包含职责和要求的完整岗位记录；搜索引擎摘要不计作脚本成功。
- **代投与回执**：没有使用招聘账号，没有填写或提交申请，无法确认自动代投能力。
- **反馈回收**：尚未连接实际邮箱、站内消息或个人申请记录；没有读取个人反馈。
- **冷却期**：没有取得适用于用户具体岗位和招聘类型的可靠规则，不能标为无限制或填入固定天数。

## 下一阶段的可复核产物

1. 三家各选择一个实际岗位：核对岗位标识、公司/业务板块、职责、任职要求、来源更新时间和申请入口，保存取得方式与缺失字段。
2. 在可用浏览器中验证动态内容，遇到需要登录的步骤，列出确切账号与权限需求。先检查表单和成功回执的识别方式，真实提交仍需对应岗位和材料授权。
3. 从用户实际使用的反馈渠道选择一个，检查消息能否可靠关联申请、识别改期和避免重复创建。
