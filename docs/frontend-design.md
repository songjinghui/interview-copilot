# 前端设计：围绕一次求职机会工作

版本：v0.3 · 2026-11-04 · 待跨个体审查；宪宪 / gpt-6-astra

范围依据：[产品愿景](../VISION.md)；接口：[应用契约](application-contracts.md)；数据：[数据库设计](database-design.md)。本文定义首版页面、操作和状态，不代表功能已实现。[可点击原型](prototypes/workbench.html)只演示关键流程，数据均为虚构。

## 1. 设计方向与技术选择

产品是个人求职工作台。主要工作是阅读 JD、比较自己的材料、记录下一步；主区域采用列表与材料正文，避免把长内容切成大量统计卡片。唯一强调的视觉元素是右侧“本次机会”上下文：岗位、当次简历、面试内容保持可见，减少选错材料。

首版推荐 **React + TypeScript + Vite 构建本机 SPA，Python + FastAPI 服务同时提供静态页面和本机 API**。不需要服务器渲染或云端部署；Python 复用现有岗位代码，并负责本地任务、文件及系统采集。用浏览器窗口承载 UI，桌面快捷入口启动/连接本机服务。UI 关闭后后台继续工作；首版不引入 Electron/Tauri 双运行时。未来需要桌面壳时复用同一应用契约。

这是待审的工程选择，不改变“纯电脑端、本机保存”的产品边界。React 官方提供从构建工具创建 SPA 的路径，同时说明路由和数据获取需要自行安排；本项目采用 URL 路由和一个类型化 API 客户端，避免再引入服务端框架。[React 文档](https://react.dev/learn/build-a-react-app-from-scratch)、[Vite 文档](https://vite.dev/guide/)。精确依赖版本在实现时验证本机 Node 兼容性后锁定，不在设计文档猜版本。

### 视觉令牌

|---|---|---|

| 工作区 | `#F2F5F9` | 页面背景与相邻内容分区 |
| 墨色 | `#23334A` | 正文、主标题 |
| 行动蓝 | `#2856A3` | 主要操作、选中项、焦点 |
| 完成绿 | `#286550` | 已保存/完成状态，附文字 |
| 核实棕 | `#805A16` | 待核实、冷却期提示，附文字 |

文字使用本机 `Microsoft YaHei UI / PingFang SC / sans-serif`，不下载字体。标题 24/32 px、分区标题 18/26 px、正文 15/24 px、说明 13/20 px；正文宽约 46 个汉字。数据无需等宽字体。统一左对齐，间距 8/12/16/24/32 px；面板圆角 8 px，按钮 5 px；分隔线而非层叠阴影区分内容。冷却期仅有适用信息时突出，未知用行内说明。

前端技能要求先自审方向：此处不使用营销首页、指标大屏、相同卡片网格；用真实操作“查看 JD / 核对简历 / 补记结果 / 校对文字”组织内容。原型以机会和材料正文作为视觉中心。

## 2. 导航与页面清单

| 页面 / 路由 | 看什么 | 做什么 | 首次/空状态 |
|---|---|---|---|
| 工作台 `/` | 下一场面试、待处理反馈、需要处理的任务、最近机会 | 进入对应记录；新建/补录 | “填写求职目标”与“补录已有面试”两个入口，不强制走完整流程 |
| 找岗位 `/jobs` | 查询条件、分来源进度、候选、原文与匹配依据 | 搜索、导入链接/文本、刷新详情、保存为机会 | 提示最少填关键词和城市/不限；未配置来源可手动导入 |
| 我的机会 `/opportunities` | 状态、最近进展、下一次行动 | 筛选、暂缓、归档、打开机会 | 可补录已投递或已有面试；不伪造搜索历史 |
| 机会 `/opportunities/:id` | 概览、岗位与材料、投递、反馈、面试时间线 | 准备投递、补记结果、添加反馈/面试、关联来源 | 缺 JD/简历明确标注，可后补；不隐藏其他操作 |
| 准备投递 `/preparations/:id` | 固定岗位/JD/渠道/简历、冷却期说明 | 一次材料确认；有冷却期第二次确认；到原渠道投递 | 无申请链接时允许复制材料与记录渠道，不编造链接 |
| 面试 `/interviews` | 按时间排列的日程与待复盘记录 | 新建、改期、取消、进入准备 | 显示时区与提醒能力；可补录过去的面试 |
| 面试详情 `/interviews/:id` | 准备 / 面试记录 / 复盘三个页签 | 选择背景版本、录音/导入、校对或写回忆、发起复盘 | 无录音仍能填回忆；缺资料提示分析局限 |
| 改进清单 `/improvements` | 按优先级与状态的行动列表、来源 | 新增、编辑、开始、完成、重新打开、忽略 | “添加一项改进”或进入已完成面试复盘 |
| 我的资料 `/profile` | 目标、真实经历、简历版本 | 编辑/确认事实、导入或编辑简历、生成材料草稿 | 不预填验证样本为用户目标；AI 草稿需确认 |
| 来源设置 `/settings/sources` | 已安装来源的分项能力、证据范围、连接情况 | 配置、启停、连接检查 | 新来源需安装对应适配器；支持导入资料作为独立入口 |
| 应用设置 `/settings` | 本地目录、模型、录音设备、启动/提醒、备份 | 配置分析发送范围、测试录音、导出/恢复预览 | 缺 ASR 模型提示设置，仍可保存音频并保留任务 |
| 后台任务 `/tasks` | 排队、处理中、暂停、需处理、已完成 | 暂停/继续/取消；处理缺文件/模型后重试 | 空时显示“当前没有后台任务”；成功任务仍可查历史 |

页签用 URL 查询参数保存，筛选、选中项和分页可回退恢复。主要导航不把任务状态、来源平台和内部实体名称各自变成新业务板块。

## 3. 关键页面与交互

### 3.1 资料与找岗

目标表单：名称、关键词（必填）、城市（至少一个或“不限”）、薪资下限及币种/周期、经验、岗位方向、目标公司、排除项。条件逐项选择“必须 / 优先”；空值与不限分开。保存后显示已保存；修改目标不更改已运行搜索的条件快照。

真实经历：类型、时间范围、职责/行动/结果、来源。导入/AI 提取先进入草稿，矛盾项标到具体字段。只有用户确认过的事实用于材料生成；缺失数据展示待补充，不制造数字。简历上传和粘贴文本均建立新版本；生成草稿展示与所用事实的对应关系，用户保存后成为可选材料版本。

找岗顶部显示关键词、城市和筛选展开区；查询进行中每个来源一行状态。列表列为岗位/公司、地点/薪资、资料完整性、条件符合/不符/未知、冷却期。有未知硬条件的岗位不直接淘汰，标为待核实；已知不符可折叠查看。匹配原因展开到具体 JD 原句，不呈现无解释的精准百分比分数。

详情右侧：岗位名、原链接、来源及获取时间、职责/要求原文、历史修订选择、匹配理由。新摘要与旧完整 JD 分别标时间；展示旧详情时写“完整 JD 来自 …，本次详情尚未取得”。保存机会时重复记录给出“打开已有机会”；疑似跨渠道重复由用户确认关联，可拆开。

### 3.2 冷却期与手动投递

```text
准备表：岗位/JD版本 + 渠道 + 简历版本 + 冷却期依据
     │ 点击“确认岗位与材料”（第 1 次）
     ├─ 无（有依据）/ 待核实 → 显示“打开投递页面”
     └─ 有 → 冷却期面板 → “知道了，继续去投递”（第 2 次）
                            或“暂不投递”
打开原渠道 → 用户自行提交 → 回到机会“补记投递结果”
```

第二次确认在当前页面内替换主操作区，避免连续弹窗；包含适用范围、说明、原始依据、已知期限，未知期限原样写未知。第一步 unknown 文案：“冷却期尚未核实，请自行核对后决定是否投递。”没有第三次授权操作。

未选择简历时须填写“此渠道无需简历”的说明，刷新后仍可见。材料/无需简历说明/岗位/渠道/冷却期依据改变会重置这份准备的确认状态，并行内说明“内容已改变，请重新核对”。刷新页面从服务读取已确认状态，不能依赖浏览器变量放行。网络重试复用请求 ID，不重复确认。

点击原链接不更新申请状态。返回后“补记结果”填写 `已提交 / 结果待确认 / 未成功`、实际时间、渠道、实际简历，可附回执或说明；已在外部提交的历史直接补录。该表记录事实，不是投递前第三次确认。用户取消/暂缓仅修改准备状态。

### 3.3 机会、反馈与日程

机会页的时间线显示投递记录、反馈、面试与结果，允许纠正并保留变更依据。归档隐藏于默认列表，可恢复。合并/拆开来源不会自动合并两段投递历史；涉及已有面试时先显示影响预览。

反馈支持文本、截图/附件及已验证只读来源。未关联进入收件区，不强猜岗位。提取的状态/日程先是建议；默认由用户确认。用户可在设置启用“明确邀请自动建面试”：仅明确唯一机会、起始时间、时区、稳定邀请键且无冲突时执行。改期复用同一场面试；冲突回待确认。最近同步成功时间与“没有回复”分开。

日程必填机会、轮次/名称、时区；未来计划需时间，历史补录可时间未知。提醒提供 10/30/60 分钟前及自定义；改期取消旧待发提醒并创建新提醒。取消面试不删除录音和复盘。电脑休眠/关机期间无法保证提醒，恢复后显示错过的提醒，不伪造准时送达。

### 3.4 录音、转写与复盘

准备页展示三项背景：岗位名称、JD 修订、简历版本；下一场可带出尚未完成的改进项。更新背景产生新版本，历史报告保留原材料。

录音操作：选择麦克风/系统声音 → 电平与短样本回放 → 用户确认录音告知/授权 → 主动开始。录音状态有持续时长与明确停止按钮。采集运行于后台；关闭页面前仅在仍录音时提示“继续后台录音 / 停止并保存”，普通后台转写无需关窗提示。设备断开时停止缺失轨道并标注缺口，恢复不偷偷开启麦克风；重启后自动处理已保存片段。

导入显示文件名、进度和保存结果；保存成功即显示“已保存，正在排队转写”，无额外开始按钮。录音或导入失败保留可恢复片段/暂存记录与具体原因。任务角标只展示数量；正常运行不弹通知打断。

文字校对：左侧音频播放器，右侧按时间排列的问答；点击时间定位音频。支持修改文字和说话人、合并/拆分片段；保存形成整份新修订。无音频回忆使用段落编号且注明“手工回忆”，没有假时间码。多个录音提供选择/组合视图，发起复盘时选定一份完整面试内容版本；组合文字通过 CombineTranscripts 生成新版本，每段显示所属录音和原始时间；相同时间码不混淆，校对后继续保留来源。不同录音的片段不合成一个假的连续时间区间。

复盘前展示四项输入及缺失提示，按钮“生成复盘”。无面试内容禁用；缺 JD 或简历允许继续，报告明确局限。首次配置模型时说明将发送哪些文字、服务与费用边界；已确认设置后本次点击即授权所展示输入的分析，不因本地转写成功自动外发。

成功转写后提供“重新转写”次要操作：用户主动操作才创建新的请求代次，同配置也可运行；旧文字与校对保留。自动恢复仍沿用原任务，不增加结果。

报告每项判断链接到固定版本的段落/时间点；旧版本可读。校对或改背景后显示“材料已更新，此报告基于旧版本”，按钮“按当前材料重新生成”。旧报告及用户改进进度保留。

报告建议可“加入改进清单”或“关联已有事项”。同一建议重复点击返回已有事项；重生成报告不自动覆盖/合并用户编辑。事项可脱离原报告继续存在，来源被主动清理后显示来源标签与已移除状态。

## 4. 状态与错误

| 场景 | 显示与恢复 |
|---|---|
| 首次加载 | 保留导航，正文骨架；不得用 0 或“没有记录”代替尚未返回 |
| 刷新 | 保留旧记录，显示刷新中及时间；失败显示旧数据时间 |
| 保存中/失败 | 按钮处理中；成功显示保存时间，失败保留本地草稿并提供重试 |
| 多窗口编辑冲突 | 显示服务最新版与本地草稿，用户选择逐项合并/放弃；不静默覆盖 |
| 服务断开 | 顶部“正在重新连接本机服务”；只读已加载数据，保留草稿，恢复后重新查任务 |
| 来源局部失败 | 失败来源行显示原因与重试；成功来源结果继续展示 |
| 不支持/未接入 | 说明具体能力不可用；显示实际证据阶段；不伪装成登录错误 |
| 转写排队/运行/恢复 | “排队中 / 正在转写 / 中断后正在恢复”；无可靠进度时不用假百分比 |
| 转写暂停/取消 | 用户控制状态持久；取消任务保留音频；继续复用原任务 |
| 需要处理 | 明确缺模型/找不到音频/空间不足；修复入口与重试，禁止无限轮询提醒 |
| 报告分析失败 | 原输入和旧报告可用；显示是否可重试及可能重复费用；未知外部结果需用户重试 |

表单草稿在服务落库前保存在浏览器 IndexedDB，页面明确“草稿尚未保存”；成功后删除对应草稿。草稿不用于业务计算、不当成系统已保存状态。纯表单草稿不包括音频、简历原件或模型凭据；凭据输入不缓存。切换记录时自动保存草稿，显式丢弃才清理。浏览器存储故障即时提示关闭页面可能丢失草稿。

可访问性：标签绑定输入；错误与字段关联；对话框限制焦点并返回触发处；Escape 关闭非破坏性浮层；颜色同时配文字；进度使用低频 aria-live；支持减少动画。AI 原文按文本/受限 Markdown 渲染，不执行 HTML、脚本或来源指令。

## 5. 前端模块与状态边界

```text
ui/src/
  app/             路由、布局、会话、错误边界
  features/        jobs, opportunities, applications, interviews,
                   improvements, profile, settings, tasks
  components/      MaterialSelector, SourceBadge, EvidenceLink,
                   CooldownNotice, TaskStatus, FormField, EmptyState
  api/             类型、请求ID、错误映射、轮询、契约客户端
  drafts/          IndexedDB 表单草稿及版本冲突恢复
  styles/          令牌与公共布局
```

服务状态由查询结果缓存管理；打开页面即读取，写成功失效相关缓存。UI 不自行推进申请/任务状态。长任务先返回 ID，任务活跃时 2 秒轮询、空闲 15 秒、隐藏页暂停 UI 轮询；恢复可见立即刷新。这不是后台工作的计时器。

URL 保存导航状态；组件 state 保存临时展开/选项；草稿保存未提交表单；本机服务是已保存事实的唯一真相。首版无需全局 Redux 或 WebSocket；后续有性能证据再调整。

## 6. 界面验收清单

1. 从空库完成目标/简历 → 找岗或导入 → 机会 → 准备 → 手动结果 → 面试 → 文字 → 复盘 → 改进；也可直接补录面试。
2. present 两次确认，absent/unknown 一次；unknown 行内提示；打开链接不显示已投递。
3. 页面重载保留确认状态和任务；内容变化重置确认；表单保存冲突可恢复。
4. 来源局部失败、JD 不完整、缺简历/音频/模型都有明确可行动的状态。
5. 转写不需手动开始；后台恢复不打断正常操作；用户暂停不会自动继续。
6. 原始材料、历史版本、报告引用可逐级回查；重算不改变已完成改进项。
7. 键盘、200% 缩放和窄窗口仍可操作；真实双声道录音、通知和休眠恢复在目标 Windows 环境单独验收，原型不证明这些能力。
