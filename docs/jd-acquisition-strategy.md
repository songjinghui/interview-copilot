# 岗位与 JD 获取方案设计

> 版本：v0.2 · 方案草案 · 2026-11-03
> 本版依据：用户提供的[岗位获取能力说明 v1.0](job-search-capability.md)，以及[美团公开岗位样本](../validation/results/public-job-2026-11-03/ASSESSMENT.md)。产品范围与用户决定以 [VISION.md](../VISION.md) 为准。

## 1. 现有证据与接入判断

能力说明记录了另一 Agent 实际搜索“AI 应用开发”的结果；本项目已有的 HTTP 探测与美团脚本是另一组证据。获取环境不同，需要分别记录，不能把普通 HTTP 的空壳结果当成渲染路径失败，也不能把 Agent 已取得的样本写成产品接入已经完成。

| 来源 | 已有证据 | 本项目接入路径 | 剩余工作 |
|---|---|---|---|
| 猎聘 | 能力说明记录 42 个岗位；列表 HTML 有标题、公司、薪资、地点，详情页有 JD | 列表 HTML 解析，候选详情逐条补齐 | 固化解析、核对职责和要求、处理部分详情登录限制与失效链接 |
| 腾讯 | 能力说明记录经渲染取得至少 9 个社招岗位及 JD；本地普通 HTTP 仅取得空壳 | 复现渲染获取，提取岗位与原文；如另有观察到的公开接口，再独立验证 | 记录可复现环境、查询条件、岗位链接与正文；不能仅凭需要渲染就断言特定浏览器库已经验证 |
| 美团 | 本地脚本已完成列表 → 编号 → 对应详情，保存原始响应 | 复用已观察并验证的公开列表、详情查询 | 条件筛选、更多样本、岗位更新与运行稳定性 |
| BOSS | 能力说明记录单个岗位详情链接可读；搜索列表未跑通 | 搜索发现的具体岗位链接、用户提供的链接进入详情解析 | 验证具体链接的可读范围，失败或缺字段时明确显示；不承诺任意链接都可读 |
| 阿里 | 集团招聘入口可达，尚无完整岗位样本 | 定位实际业务板块与岗位列表，再选择获取方式 | 列表、详情与申请入口 |
| 字节 | 能力说明记录页面结构与搜索线索，尚未跑通完整岗位获取 | 作为扩展候选验证渲染或有来源证据的公开查询 | 不增加为首版必交付来源 |

42 个和至少 9 个仅指文档记载的当次搜索数量。现有记录不足以给出覆盖率、长期成功率或跨环境稳定性。具体能力范围与来源状态见 [愿景 4.2](../VISION.md#42-来源岗位质量与跨渠道管理)。

## 2. 按来源选择获取方式

### HTML 列表与详情

猎聘已有列表 HTML 的实测依据，先实现并验证列表解析；对候选补取详情，分别检查职责和任职要求。登录页、验证页和内容缺失不能记为完整 JD，页面返回 HTTP 200 也不能作为找岗成功标志。

### 页面渲染

腾讯已有渲染后取得岗位的实测记录，接下来将这条路径迁入项目并保留可复现条件。Playwright 可作为待验证实现候选，现有能力说明未给出其确切渲染引擎版本和运行配置，不能声称本项目已用 Playwright 跑通。

以岗位卡片、职责和要求是否实际出现作为内容检查依据。页面仍在加载或只出现壳结构时保留失败原因；需要人工登录或验证时显示具体步骤，不将取得一个页面等同于取得完整数据。

### 有来源证据的公开查询

美团的接口路径及参数来自本轮官网公开脚本，已经在未登录条件下取得列表及对应详情。现有验证命令：

```powershell
python -X utf8 validation/probe.py --companies 美团 --skip-platforms --meituan-job-sample --output-dir validation/results/public-job-2026-11-03
```

脚本固定读取第一页中的一个岗位，再查该岗位详情；两个 POST 都是读取查询，没有调用投递、简历保存或消息接口。这是样本验证工具，尚未实现用户条件搜索与完整来源接入模块。

其他来源的接口需要从实际页面、公开脚本或正常使用中的请求获得路径和参数，再验证响应；旧草案列出的腾讯、字节、猎聘接口猜测不作为已知可用接口保留。网页使用的接口也不自动等于对外承诺稳定的开放 API。

### 单个链接与资料导入

BOSS 当前按单个岗位链接读取处理，不宣称搜索列表已可获取。用户提供链接后仍须验证其可访问性；截图、粘贴文本或手动补记是独立的资料入口，并标记内容来源与缺失字段。链接导入仍依赖页面可访问，不能宣称它天然不受访问限制影响。

## 3. 搜索到候选清单的流程

1. 用户确定关键词与城市（可选“不限”），按需补充薪资、经验、技术方向、目标公司和现有链接。验证样本不自动转成用户偏好。
2. 按来源能力执行一次搜索或读取具体岗位链接，保存实际查询条件、原链接、岗位标识、时间与获取方式。
3. 将来源记录关联为机会，标记疑似重复；按已有硬条件初筛，未知字段保留未知，不据此判定满足条件。
4. 为候选取得职责与任职要求。列表中已有两部分原文时可直接使用；只有摘要或职责时继续补齐，未补齐前不标为完整 JD。
5. 结合用户确认的经历给出匹配理由，区分原文事实与 AI 判断；不承诺未经评估的匹配分数准确率。
6. 找岗阶段即标注投递限制或冷却期，来源不明时为待核实。输出岗位、公司、薪资、地点、经验、匹配理由、原链接、资料完整性和限制状态。
7. 用户选岗后进入投递准备与授权流程。当前可演示路径输出原链接，由用户投递并补记；未来经验证支持的渠道按既有授权规则代投。

行业新闻及搜索摘要只提供背景或岗位线索，不能当作完整 JD、当前仍在招聘或公司冷却期的证据。本版不引入未经一手来源核对的招聘比例、薪资行情等统计结论。

## 4. 字段、扩展与失败处理

| 记录内容 | 处理要求 |
|---|---|
| 来源与岗位标识 | 原链接、来源岗位 ID（如有）、渠道、获取时间、获取方式与来源更新时间分别保留 |
| JD 原文 | 职责与任职要求分别保存和判断完整性，保留原始内容及历史版本 |
| 薪资、经验、学历、地点 | 缺失保留未知；保留薪资原始单位及薪数，不将不同口径直接比较 |
| 公司与发布者 | 匿名名称保留原样；公司、猎头或其他发布者分开，不猜测真实雇主 |
| 能力与运行状态 | 另一 Agent 实测、本地复现、产品接入分别记录；搜索、详情、投递、回执、反馈各自声明能力 |
| 失败与访问条件 | 区分空结果、解析失败、内容不完整、登录要求、验证页、请求失败；不把未取得数据写成没有岗位 |

来源接入模块承担获取和字段映射，机会管理、冷却期、材料版本、日程与复盘复用统一记录。新增来源应主要增加接入模块、映射和测试；现阶段 `probe.py` 是独立验证脚本，不视为产品架构已经实现。

按用户需要获取岗位、控制请求量；本地美团样本不翻页或重试。生产接入的频率根据各来源的实际限制与验证结果确定，不把旧草案中的固定请求频率当作平台许可。当前验证不读取登录凭据、私人消息或提交申请。

## 5. 接入与验收顺序

| 步骤 | 工作 | 应交付证据 |
|---|---|---|
| V1 | 固化猎聘列表与详情，复现腾讯渲染路径，并复用美团脚本样本 | 查询条件、工具与版本、实际岗位 URL/ID、职责和要求原文、缺失字段与失败记录 |
| V2 | 接入第二个真实来源并核对统一记录 | 原有来源回归通过、重复获取不重复建档、停用来源后历史仍在 |
| V3 | 验证 BOSS 的具体岗位链接；继续寻找阿里业务板块入口 | 单岗可读范围、内容完整性、无法读取时的状态；阿里实际岗位证据 |
| V4 | 使用用户实际条件验证筛选、更新与失效处理 | 逐条人工核对的匹配理由、条件缺失和岗位变更记录 |
| V5 | 独立验证投递、回执和反馈 | 对应账号与材料授权、实际提交结果或未执行原因、反馈关联与去重；不从找岗成功推断通过 |

既有验证工具使用 Python、requests 和 BeautifulSoup；本次只调整方案，不新增依赖或确定尚未验证的浏览器技术栈。行为实现继续遵守测试先行，并运行完整测试套件。

## 6. 已定事项与待补充信息

- 首批服务用户本人；用户选岗、授权材料后希望 AI 代投，目标保持不变。
- 首批来源为猎聘、BOSS 和企业官网；企业官网样本为阿里、腾讯、美团。来源应可扩展，无需重复询问公司名单。
- 用户当前岗位方向、城市与招聘类型仍需落实为搜索条件；“AI 应用开发”是能力说明的验证关键词。
- 当前能力说明不支持代投和个人消息读取，仅说明当次工具能力。未来接入仍需逐渠道验证；不要求用户现在导出 Cookie 或提前授权未明确的数据范围。
- 实际反馈渠道和账号连接在对应验证环节确定。语音、本地存储与模型分析的边界继续以愿景文档为准。
