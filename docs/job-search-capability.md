# 岗位获取能力说明

> 版本：v1.0 · 2026-11-03
> 基于实际搜索"AI 应用开发"岗位的验证结果编写，非推测。

## 1. 能做什么

以"AI 应用开发"为关键词实际跑通后，确认以下能力可用：

| 能力 | 说明 |
|---|---|
| 搜索岗位 | 输入关键词 + 城市，从猎聘、腾讯招聘官网等渠道拿到岗位列表 |
| 获取完整 JD | 腾讯官网搜索页直接包含完整职责描述；猎聘列表页有标题/薪资/地点，详情页有完整 JD |
| 筛选匹配 | 拿到岗位后按城市、薪资、经验、技术方向过滤，与用户经历比对 |
| 输出清单 | 每个岗位附原链接，用户点进去即可查看或投递 |
| 行业概况 | 通过搜索新闻和招聘报道，了解哪些大厂在招 AI 岗、薪资行情、校招/社招节奏 |

**不能做的**：替你登录平台、替你提交简历、替你读取站内消息。投递和反馈需要你本人操作。

## 2. 各渠道实际验证结果

### 猎聘（最容易拿到数据）

- **搜索页**：`liepin.com/zhaopin/?key=关键词` 直接返回带岗位卡片的 HTML，无需 JS 渲染
- **实测**：搜"AI应用开发"一次性拿到 42 个岗位，包含标题、公司、薪资、地点
- **完整 JD**：列表页有摘要，详情页有完整职责和要求
- **限制**：部分详情页可能需要登录才能看完整内容；平台有反爬，不适合高频请求
- **投递**：需要用户登录猎聘账号操作

### 腾讯招聘官网

- **搜索页**：`careers.tencent.com/search.html?keyword=关键词`，纯 JS 渲染，`requests` 拿到空 HTML，但用渲染引擎可以拿到完整数据
- **实测**：搜"AI 应用开发"拿到至少 9 个岗位，每个都带完整 JD（职责描述）
- **优势**：JD 质量高、结构清晰，直接包含职责和技术要求
- **限制**：需要 JS 渲染才能获取；投递需要登录腾讯招聘账号
- **覆盖**：社招岗位，按事业群（IEG/WXG/PCG/S3 等）分类

|---|---|---|---|

### BOSS 直聘

- **搜索页**：`zhipin.com/web/geek/job?query=关键词`，纯 JS 渲染，WebFetch 拿到"加载中"空壳
- **替代路径**：通过 WebSearch 可以搜到 BOSS 上的具体岗位详情页（如 `zhipin.com/job_detail/xxx.html`），这些详情页可以被读取
- **限制**：反爬最强，不适合自动化批量获取；投递和沟通需要用户在 APP 或网页端操作
- **可用方式**：用户在 BOSS APP 中看到岗位后，复制链接给助手，助手可以读取该岗位详情页内容

### 字节跳动招聘官网

- **搜索页**：`jobs.bytedance.com/experienced/position`，纯 JS 渲染
- **实测**：WebFetch 可拿到页面结构，但岗位数据需要完整 JS 执行
- **替代路径**：通过 WebSearch 可搜到字节岗位（含校招和社招），新闻报道确认字节有 AI 全栈工程师、AI Agent 开发等岗位
- **限制**：需要 JS 渲染或手动浏览；投递需要登录

### 行业新闻与报道

- **用途**：快速了解大厂 AI 招聘趋势、岗位类型、薪资行情
- **实测**：搜到 2027 届校招报道，确认腾讯新上架 AI 全栈工程师、Agent 开发工程师、AI 应用工程师；字节首次上新 AI Agent 开发；阿里 AI 岗位占比 80%；百度 AI 职位占比超 90%
- **限制**：新闻报道偏校招和宏观趋势，社招具体岗位仍需从招聘平台获取

## 4. 范围与限制

### 不在能力范围内

1. **代投**：所有渠道的投递都需要用户本人登录操作，助手不能替你提交简历
2. **读取站内消息**：BOSS/猎聘的站内沟通需要登录，助手无法自动读取
3. **批量抓取**：平台有反爬和风控，不适合大规模自动化采集
4. **实时监控**：当前方案是按需搜索，不是持续监控新岗位发布
5. **BOSS 列表页**：BOSS 搜索页纯 JS 渲染且反爬强，无法直接获取列表；只能通过用户提供的链接读取单个岗位详情

### 数据时效性

- 搜索结果反映的是搜索时的招聘状态，岗位可能随时下线或更新
- 建议获取后尽快查看和决策；隔天可能已变化
- 腾讯官网岗位有"更新于"日期，可判断活跃度

### 准确性

- 薪资和经验要求以平台展示为准，实际可能有出入
- "某知名公司""某大型互联网企业"等匿名发布在猎聘上较多，需点进详情页确认
- JD 内容以原文为准，助手的解读和匹配建议仅供参考

## 5. 实际操作流程

```
用户给出条件（关键词 + 城市 + 薪资 + 经验）
        |
        v
  同时搜索多个渠道
  ├─ 猎聘搜索页（直接拿 HTML 中的岗位列表）
  ├─ 腾讯招聘官网（渲染后拿岗位 + 完整 JD）
  ├─ WebSearch（补充 BOSS/字节/新闻中的岗位线索）
  └─ 用户提供的链接（如有）
        |
        v
  合并去重，按条件筛选
        |
        v
  对筛选通过的岗位，逐个获取完整 JD
        |
        v
  拆解 JD 要求，与用户经历比对，标注匹配度
        |
        v
  输出清单：岗位标题 / 公司 / 薪资 / 地点 / 匹配度 / 原链接
        |
        v
  用户自行点击链接查看和投递
```

## 6. 技术路线（供实现参考）

| 渠道 | 获取方式 | 说明 |
|---|---|---|
| 猎聘列表 | HTTP 请求 + HTML 解析 | 岗位卡片在服务端渲染的 HTML 中，`requests`/`httpx` 直接可取 |
| 猎聘详情 | HTTP 请求或渲染引擎 | 部分详情页可能需要 JS 渲染 |
| 腾讯官网 | 渲染引擎或 Playwright | 纯 JS 渲染，需执行 JS 后提取数据或拦截 XHR |
| BOSS 详情页 | HTTP 请求 | 单个岗位详情页可被读取；列表页不行 |
| 字节官网 | Playwright（待验证） | 纯 JS 渲染，需无头浏览器 |
| 行业新闻 | WebSearch | 补充宏观信息和校招动态 |
| 用户导入链接 | HTTP 请求或渲染引擎 | 用户提供的任意岗位链接，助手读取后解析 |
