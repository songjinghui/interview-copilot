# M1：把已有简历变成可复用的个人资料

状态：草案 v1，待用户审阅；当前首个业务审阅块。返回[总览](README.md)；数据交接见[data-flows](data-flows.md)。

## 1. 完成后你能做什么

拿已有HTML简历进入应用，核对导入内容后直接查看当前简历；系统从同一份原文整理经历草稿，你只改错和补缺，不重新填一套同内容表单。之后再次打开、修改资料或为岗位选择简历，都能复用已保存记录。

本块不要求先填写求职目标，不要求先接入招聘网站，也不强制所有经历都确认后才允许查看或使用已保存的原简历。

## 2. 功能边界和两个可验收子段

| 子段 | 本次应完成 | 可独立展示的结果 |
|---|---|---|
| M1a 导入、查看和版本 | HTML、带文字层的PDF、粘贴文本；本机预览；核对保存；默认简历；编辑另存版本；重开恢复 | 一份真实保存、可以继续使用的当前简历 |
| M1b 经历整理与复用 | 从固定简历正文生成有原文依据的经历草稿；核对/确认/忽略；补缺与冲突处理；新版本采用已确认事实 | 资料整理无需整份重填，事实可以用于后续材料生成 |

M1a可先验收并使用；只有M1a通过不能将M1整体标为完成。M1b不是无限等待的“后续优化”。两个子段均需先通过其需求/数据/界面审阅，再实施。

本块不新增OCR、所有办公文档格式、外部聊天记录自动读取、排版设计器或云同步。既有PDF候选实现保留并验收；HTML作为你当前材料的主验收样本。生成针对某岗位的材料属于M3。

## 3. 用户操作与页面状态

| 场景 | 页面重点 | 用户操作 | 系统结果 |
|---|---|---|---|
| 尚无简历 | 导入已有简历，粘贴文字为另一入口 | 选择文件/粘贴 | 本机提取并展示预览，不跳去长表单 |
| 预览中 | 提取正文与文件信息，明确尚未保存为正式简历 | 修正文字后保存，或退出稍后继续 | 正式保存后展示全文；导入草稿可恢复 |
| 已有一份 | 当前简历全文、名称/版本、少量整理状态 | 阅读、编辑、查看原件/历史 | 新增/导入为次级操作，目标表单不挡正文 |
| 有多份简历 | 明确一份默认简历，提供切换列表 | 选择查看或设为默认 | 新导入另一份不会悄悄改变默认 |
| 经历待核对 | 同一资料工作区中显示草稿及对应原文 | 批量确认无冲突条目，逐项修正冲突/忽略 | 确认后可供生成材料使用，未确认内容继续标草稿 |
| 编辑现有内容 | 进入编辑态后才出现完整编辑控件 | 保存新版本或放弃本次编辑 | 保留旧版本及历史投递引用 |
| 文件/解析/整理失败 | 保留原材料或导入草稿，说明失败步骤 | 修正、重试或继续使用已保存正文 | 不制造空“成功”记录，不丢已输入文字 |

## 4. 数据拆分

| 对象 | 最少内容 | 规则 |
|---|---|---|
| 原件与导入草稿 | file_assets的文件名/媒体类型/相对路径/哈希/状态/意图，以及可恢复预览正文 | 本机处理；HTML不执行脚本；正式确认前不是已保存简历 |
| 简历身份 | materials.id、label、archived_at | “主简历”和“针对某岗位的简历”可以是不同身份；不把每个版本都建成另一份简历 |
| 简历版本 | material_id、revision、text_content、file_asset_id、fact_snapshot | 不可变；编辑新增版本；新导入明确选择“另一份”或“已有简历的新版本” |
| 经历事实 | profile_facts的类型、内容、状态、来源、revision | 草稿与已确认分开；日期保留原文与精度；缺数字不补数字 |
| 整理任务 | material_draft任务，purpose=extract_facts，固定源版本、配置和结果身份 | 不依赖页面存活；同任务重试不重复建条目；改变源版本须新任务 |
| 默认选择 | settings的profile.default_material_id | 指向存在且未归档的材料；日常取其最新版本；下游自行固定具体版本 |

候选实现可复用已有资料命令、版本约束、PDF/HTML提取和草稿机制。新增的整理、默认选择与日期精度规则见共享文档D1–D3、D7；它们尚未实现，不修改旧迁移来假装已有。

## 5. 业务与数据交互

1. 用户开始导入→本机保存暂存资产/导入意图→提取正文，展示可恢复预览。暂存与正式资料状态有明确区别。
2. 用户确认正文→ImportMaterial，以同一request_id发布资产和材料版本；第一份材料同时设默认。文件发布中断按日志恢复，不生成引用缺失文件的成功记录。
3. 用户已配置并允许相应文字整理后→ExtractProfileFacts固定刚保存的version_id，后台提取草稿；只发布能定位原文的条目。失败不影响已保存简历阅读。
4. 结果与现有经历比较→相同内容提示复用；疑似同一经历或冲突交用户判断，不自动覆盖。算法建议不是事实。
5. 用户修正并ConfirmFact→事实进入confirmed；用户修改已确认事实后回到待核对状态。支持核对一组无冲突项，避免机械逐字段重复确认。
6. 用户编辑或在M3生成新材料→SaveMaterialVersion固定parent和所用已确认事实快照。不会回改导入版本或原件；同一次重试返回同一版本。

“保存简历正文”与“确认抽取的事实”语义不同：前者表示用户认可这份材料可用，后者用于审查系统是否正确整理了经历。不能让未完成自动整理阻断原简历用于投递，也不能把自动抽取默认当成用户确认。

## 6. 先写的验收场景

| 编号 | 输入/操作 | 必须看到的结果 |
|---|---|---|
| M1-A1 | 空库导入合成HTML，核对保存后关闭页面和服务再打开 | 当前正文、版本、原件仍在；只有一份正式记录 |
| M1-A2 | 已有v1，进入页面/编辑另存v2 | 默认展示正文；新增次要；v1保持可读；返回查看态 |
| M1-A3 | 一份简历已有申请引用，后来切换默认并修改 | 历史申请仍指向原版本；无静默替换 |
| M1-A4 | 重复点击保存、断线后同请求重试、同文件再次导入 | 前两者幂等；再次导入提示已有内容并让用户选用途，不偷偷创建一串重复版本 |
| M1-A5 | 原文含两段工作经历和缺失日期/数字 | 草稿对应原文；缺失项保持未知；无需整份重填；确认后可引用 |
| M1-A6 | 已确认经历与新文件冲突；整理任务重试/服务重启 | 保留原确认事实，冲突待核对；重试不重复建草稿，恢复后仍可处理 |
| M1-A7 | HTML含脚本、PDF无文字/加密、损坏/超限文件 | 不执行HTML；具体失败与恢复入口；原资料和草稿保留 |
| M1-A8 | 两窗口改同版本；导入中断、主动丢弃预览 | 冲突不覆盖；中断可恢复；丢弃不生成正式资料且不删除其他资料 |

## 7. 本块待审决定与准入

建议采用：①默认以已有简历为中心，目标不阻挡导入；②导入后自动整理成待核对经历，允许先使用正文；③多份简历显式默认、历史投递固定版本。

技术准入由负责人补齐：以合成/获授权样本验证结构提取质量、年月精度、文件限制、持久草稿及实际交付环境。模型具体服务、发送文字范围和成本尚未选定，不能把M1b标为可实现验收完成；接入前提供具体方案和所需授权，不扩大到读取外部聊天历史。已有上传候选代码须重新审查并验收，不能凭先前测试数直接合并。
