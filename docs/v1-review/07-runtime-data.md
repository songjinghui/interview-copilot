# G：贯穿业务块的运行与数据保障

状态：草案 v1，待审；随各块审阅，首版发布前完整收口。返回[总览](README.md)。

## 1. 随何时交付

| 时点 | 需要具备的能力 | 用户看到的结果 |
|---|---|---|
| M1起 | 统一启动入口/鉴权、前后端版本一致、文件暂存与持久草稿、保存/冲突/恢复、资料基本管理 | 稳定打开，已保存与未保存清楚，重开不丢资料 |
| M2起 | 持久任务、来源隔离、重试/暂停/取消、配置与凭据隔离 | 来源失败不拖垮其他工作，后台进度可信 |
| M4/M5起 | 日程提醒、后台运行/系统恢复、真实音频与worker生命周期 | 关闭窗口仍按说明工作，恢复后继续任务，错过提醒有记录 |
| 首版完整交付前 | 一致备份、隔离恢复、显式清理/导出、全流程与升级回归 | 可以找回自己的数据，了解删除影响，安装版本可实际使用 |

这是一组共用约束，不新增一个独立业务系统。Task Scheduler等系统注册如需启用，在具体交付方案获授权后执行，本轮不修改电脑配置。

## 2. 数据管理操作

- 默认永久保存用户记录、草稿、任务结果与历史，没有自动TTL。归档可恢复；用户主动丢弃一次导入草稿的范围必须明确。
- ExportBackup取得一致的SQLite快照和资产清单，包含已选择范围内所需原件/音频，不显示遗漏文件的“成功备份”；凭据不导出。
- PreviewRestore检查结构版本、清单/哈希、资产和引用，再由用户选择范围；ApplyRestore先在新目录恢复并验证，保留原目录，不能直接覆盖唯一副本。
- 显式清理先列影响：原音频、文字、报告、申请引用各是什么；仍被引用的对象按约定阻止或保留可追溯标记，不随意级联删除。
- settings保存经验证的配置与凭据引用；密钥使用系统凭据机制。AI原文按文本/受限格式显示，不能执行其中的HTML/脚本或指令。
- 首版无跨设备同步；未来可同步实体与本地音频/转写/报告全文分层，备份去向不默认成为云服务。

## 3. 一次交付必须核对的链

代码提交→前端构建→正确后端进程→正确静态目录→应用自己的启动/鉴权入口→隔离数据目录→实际用户操作。

记录具体提交和运行实例，确认新前端请求确实到支持该协议的后端；重启服务不能只重开旧进程页面。服务ready只证明健康检查，不证明文件上传、保存、转写等业务成功。交付说明列清已验证范围，不能反复让用户刷新来替代诊断。

运行数据使用隔离开发/验收目录。未合并实现放功能工作区测试；合并后在独立验收环境验证。已有原型、其他工作树和用户日常数据库不自动纳入本次改动或清理。

## 4. 测试与验收执行约定

按仓库AGENTS规则，所有改变可观察行为的修改先新增/更新目标测试，运行并确认旧实现因目标行为错误或缺失失败；然后修改实现，再运行目标测试和完整套件。配置或语法错误不算有效红测。

当前项目完整测试命令（仓库根目录；进入frontend的两条命令在该目录运行）：

~~~powershell
python -X utf8 -m unittest discover -s tests -t . -v
python -X utf8 -m unittest discover -s validation/tests -p 'test_*.py' -v
Set-Location frontend
npm test
npm run build
Set-Location ..
python -X utf8 scripts/verify_workbench_runtime.py
git diff --check
~~~

完整测试包括Python产品套件、validation套件和前端套件。构建和安装运行探针补充交付检查；迁移/设计契约变更时再运行docs/design-checks/validate_design.py并核对schema-reference，不把设计SQL通过当作运行迁移通过。依赖按锁文件在隔离工作区安装；新增工具以仓库实际脚本为准。

纯文档本轮仅检查链接、覆盖与一致性，不宣称运行了产品测试。实际实现测试如受环境限制，写清命令、错误和未验证项目，不能标为已验证完成。

界面自动化与真实浏览器验收各有职责：用组件/HTTP测试验证保存和状态；用运行页面验证有内容的首屏、主要操作位置、字段密度、窄窗口、键盘、200%缩放。空库截图不能代表有资料状态；DOM断言不能证明布局可读。

## 5. 发布与故障场景

| 编号 | 场景 | 完成证据 |
|---|---|---|
| G-A1 | 全新安装、旧库升级、两窗口并发 | 真实安装包可开；迁移保留旧记录和引用；并发冲突不覆盖 |
| G-A2 | 前后端升级后走本块主路径 | 实例版本对应、鉴权正常；实际导入/保存/读取成功 |
| G-A3 | 导入/保存中断、文件替换、路径越界 | 可恢复意图与草稿；未发布半成品；错误明确 |
| G-A4 | 关窗/杀worker/服务重启/休眠/登录恢复/主动停后台 | 相应任务恢复或保持暂停；无重复产物、无私自重开录音 |
| G-A5 | 备份后在另一隔离目录恢复 | DB与资产一致；版本引用、已完成改进及任务控制状态正确 |
| G-A6 | 归档、取消、显式清理 | 日常状态变化不删历史；清理只作用于确认范围 |
| G-A7 | 完整首版路径及直接补录路径 | 每块交接ID/版本正确，真实来源与真实ASR均有证据；缺材料路径诚实可用 |

当前共有设施复用现有storage、session、launcher和API边界。不要为每块单独搭服务，也不要为了先交付页面把持久化推迟到以后。
