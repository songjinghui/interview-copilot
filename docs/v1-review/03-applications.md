# M3：围绕一次机会准备并记录投递

状态：草案 v1，待顺序审阅。返回[总览](README.md)；共用[data-flows](data-flows.md)。

## 1. 结果与边界

用户选定岗位，复用资料准备材料，核对本次冷却期，在原渠道手动投递，再记录发生的结果。应用中“准备好了”“已打开网页”“已提交”保持不同含义。

首版不自动填平台表单、不发送简历/消息、不点击对外提交。不设练手/重点分类，不增加跨岗位限制推演和第三次投递授权。已有历史可直接补录。

## 2. 功能拆分与页面

| 子段 | 用户流程 |
|---|---|
| M3a 选岗和机会 | 加入机会、查看多来源JD及历史投递、暂缓/恢复、确认关联或拆开、归档 |
| M3b 准备材料 | 选已有简历版本或基于真实经历生成岗位材料草稿；看差异与依据，保存后用于本次准备 |
| M3c 手动投递与补记 | 确认岗位/渠道/材料；有冷却期再确认一次；打开原渠道；回来补记结果、时间和依据 |

机会详情优先展示当前岗位、已选材料、已有进度和下一步。只有点击准备、修订或补记时展开相应表单。缺原申请链接时可复制材料并记录渠道；不能制造链接。没有简历但渠道确实不需要时，保存明确说明。

## 3. 数据和交接

| 对象 | 关键关系与写入 |
|---|---|
| 机会 | opportunities可关联多个opportunity_jobs；同来源同岗位重复加入返回已有机会 |
| 材料草稿 | material_draft任务固定目标JD、基版、已确认事实快照及模型配置；结果需用户保存为M1的material_version |
| 冷却期 | cooldown_notes追加适用判断与原始依据，引用M2观察或用户提供信息；修正追加新note，不修改旧依据 |
| 准备 | application_preparations固定JD/简历版本、渠道、无需简历说明、冷却期快照及确认状态 |
| 申请事实 | applications固定当次材料和真实结果；application_events保留每次修正的快照和理由 |

SaveOpportunity→按证据RecordCooldown→选材/生成草稿并保存→SavePreparation→ConfirmPreparation→用户外部操作→RecordApplication。跨块都传明确version_id；不把M1默认材料变化自动带入已确认准备或历史申请。

更改准备中的岗位、材料、渠道或冷却期依据会清除相关确认。解除关联后不能继续用已解除岗位完成准备；旧申请引用仍可读。材料生成仅使用确认事实，缺失事实提出待补充项，不能补造数字或资历。

## 4. 状态规则

| 情况 | 应有行为 |
|---|---|
| present 有适用冷却期 | 材料确认→冷却期确认→可去原渠道；允许暂缓 |
| absent 有依据无冷却期 / unknown 待核实 | 一次材料确认；unknown同时提示待核实，不追加确认 |
| 只打开原页面 | 仍未记录实际提交 |
| 用户明确补记已提交 | 必须有实际时间与依据；记录成功事实 |
| 外部结果不清楚或未成功 | 保留对应结果，不能用准备状态推算已投递 |
| 补录既往申请 | 直接记录历史及当时材料，不要求倒走准备确认 |
| 修正历史时间/回执 | 保留当时材料/准备快照，记录修正原因，不混入后来修改 |

## 5. 验收

| 编号 | 场景 | 标准 |
|---|---|---|
| M3-A1 | 从M1版本及M2岗位准备一次投递 | 无重复录入；材料/JD可回查 |
| M3-A2 | 三类冷却期、修改材料后再确认 | 次数分别2/1/1；改关键输入重置确认；刷新状态保持 |
| M3-A3 | 生成材料草稿、失败或用户取消 | 事实有来源；草稿未保存不成为正式版本；原材料保留 |
| M3-A4 | 打开链接、结果未知、明确补记 | 只有有依据的补记更新事实；双击/断线重试不重复申请 |
| M3-A5 | 后来修简历/JD、纠正旧申请 | 旧申请固定版本和修正历史仍一致 |
| M3-A6 | 多渠道关联/解除、已有申请直接补录 | 不串机会、不合并两段投递历史，不伪造确认记录 |

测试位置：tests/test_application.py、test_application_review.py、test_application_validation.py、test_http.py及frontend/tests/journey.test.tsx。现有准备/投递服务是复用基础；AI材料生成和真实页面路径须另验。验证对外投递时用模拟原渠道或用户操作，不由测试向真实企业提交。

准入：M1/M2接口可复用，或已有资料/JD通过补录取得；使用外部文字模型须沿用已配置的服务与明确范围，不能把模型成功等同于材料正确。
