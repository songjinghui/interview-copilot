# M6：有依据的复盘与持续改进

状态：草案 v1，待顺序审阅。返回[总览](README.md)；共用[data-flows](data-flows.md)。

## 1. 结果与边界

用户选择一场面试，看到具体问题、回答证据和可执行建议，并把有用建议加入自己的改进清单。下次准备可以继续使用，完成进度不会被重新分析覆盖。

四项输入固定为岗位名称、JD、简历、面试内容。缺JD/简历允许有局限的复盘，缺面试内容不能生成。原始事实、分析判断和建议分开；没有被问到的能力不能直接判定为不足，不预测录用概率。

## 2. 功能拆分与页面

| 子段 | 用户流程 |
|---|---|
| M6a 输入与报告 | 核对四项输入和版本/缺项→按已配置文字分析边界发起→查看报告及可跳转证据 |
| M6b 改进清单 | 采纳/关联已有事项、自己补充行动、设优先级、编辑备注、开始/完成/忽略/重新打开 |
| M6c 反馈到下一轮 | 材料更新提示报告过期；重新生成保留旧报告和行动；M4准备页读取未完成项 |

已有报告优先展示正文、证据和改进，不把“生成”大表单持续放在主位置。报告显示来源和局限；用户点击证据回到固定版本，不跳到后来修改的文字。

## 3. 数据与交互

| 对象 | 关键数据 |
|---|---|
| 复盘任务 | background_tasks；review_runs固定interview_id、context_version_id、transcript_version_id、model_config、prompt_revision |
| 报告 | review_reports与run一对一，正文区分事实/判断/建议，每条引用携带版本、段落和可用音频定位 |
| 行动 | improvement_items独立保存title/action/priority/status/user_note/usefulness/completed_at/revision |
| 来源 | improvement_origins关联报告建议；同报告同建议唯一；多报告可关联已有行动 |

GenerateReview检查两份版本属于同场面试→保存任务和固定输入→事务外调用模型→校验引用和报告结构→发布报告。引用不存在或跨面试则拒绝发布为完整报告，并保留可诊断错误。

AddImprovement从明确建议创建或关联现有项；重复点击返回已有结果。UpdateImprovement只修改用户行动，done保存完成时间，重开清除完成时间。报告重生成不自动合并语义相似事项，不改用户文字或完成状态。

M1改简历或M5改文字不会改旧run；提示“此报告使用旧材料”，由用户发起新报告。来源被显式清理后，改进项仍保留来源标签和已移除说明，不能级联丢失用户工作。

## 4. 模型和失败边界

使用已说明并配置的文字模型服务，界面展示本次输入；按配置授权发送所需文字。音频不随之上传。应用不做转写全文的云存储/同步；服务商留存条件另行核实，不据此宣称服务商零留存。

请求失败保留输入和旧报告；网络结果不确定时说明可能已处理/计费，由用户明确重试，不无限重复收费。新模型或发送范围/成本变化按具体配置重新说明，不借后台转写成功自动外发分析。

## 5. 验收

| 编号 | 场景 | 标准 |
|---|---|---|
| M6-A1 | 完整四项输入、缺JD/简历、无内容 | 分别正常/说明局限/禁止生成；无伪造材料 |
| M6-A2 | 固定版本后修改简历或文字 | 旧报告仍引用旧版，显示更新提示；新报告独立 |
| M6-A3 | 模型返回不存在/跨面试引用 | 校验拒绝，不能展示成可信证据 |
| M6-A4 | 重复采纳、关联同一行动、完成后重算报告 | 不重复创建、不丢用户修改、不重新打开已完成项 |
| M6-A5 | 外部超时、结果未知、关窗/重启 | 输入和任务可恢复；费用风险明确；原报告保留 |
| M6-A6 | 授权样本人工审阅及下一轮准备 | 结论有原话依据，区分未覆盖；建议具体；未完成项可进入准备页 |

测试位置：新增tests中的review/improvement领域和HTTP测试，frontend/tests中的报告/行动旅程；自动化固定模型响应验证约束，真实授权样本人工检查分析质量。测试模型返回格式正确不能替代复盘有用性。

准入：负责人完成具体模型/成本/留存边界验证，与M1/M3共用已确定的文字服务适配，不重复建立三套配置。首版结束前走一条包含材料、岗位、申请、面试、内容、复盘、下一轮行动的真实隔离路径。
