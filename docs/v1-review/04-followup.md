# M4：跟进反馈、安排面试并集中准备

状态：草案 v1，待顺序审阅。返回[总览](README.md)；共用[data-flows](data-flows.md)。

## 1. 结果与边界

用户知道每个机会进行到哪里、最近收到什么、下一步做什么，并能安排或补录一场面试，集中查看当次材料。支持从已有邀请进入，不要求先在本应用找岗或投递。

只读反馈来源和实际渠道仍需选定、授权及验证；手动导入可以先用，但不能因此把只读接入标为完成。不自动回复招聘方，不推断未回复就是拒绝。

## 2. 功能拆分

| 子段 | 操作与结果 |
|---|---|
| M4a 进度与反馈 | 导入文本/截图、补记电话或笔试进度；保留原文；整理建议关联机会和下一步；用户确认冲突 |
| M4b 日程与准备 | 手动新建/补录、邀请提取、改期/取消、多轮；准备页展示当次岗位名、JD、简历、相关经历与未完成改进 |
| M4c 只读同步与实际提醒 | 接入已授权来源，离线补取去重；按配置处理明确邀请；在目标电脑验证提醒与错过提醒 |

机会页优先时间线、当前结果和下一步；未关联消息进入待处理列表。日程页优先已有安排，新增表单按需出现。首页汇总这些真实记录；读取失败不显示为没有任务。

## 3. 数据与交互

| 对象 | 数据关系与变化 |
|---|---|
| 反馈 | feedback_items保留原文/附件、发生和接收时间、账号及外部键、建议、处理状态；建议和确认结果分开 |
| 同步 | sync_cursors按账号+入口记录游标及最近成功时间；一页消息落库与游标推进同事务 |
| 机会进度 | ResolveFeedback调用机会写入命令，confirmed依据可回查；笔试等细节留在反馈时间线，不滥用面试完成状态 |
| 面试 | interviews归属机会；application_id可空；稳定邀请身份是账号+事件键，改期复用同一ID |
| 背景 | interview_context_versions固定岗位名称、JD版本、简历版本及缺项；缺材料允许补录并标明 |
| 提醒 | reminders关联面试或冷却期核验记录；pending/delivered/missed/cancelled/acknowledged真实区分 |

ImportFeedback/SyncFeedback→提取建议→ResolveFeedback→确认机会变化或SaveInterview→SaveInterviewContext→创建提醒。用户手动创建可直接SaveInterview，不先制造反馈或申请。

自动建日程仅在用户开启该能力、唯一机会/邀请身份、明确起始时间和时区、无冲突时执行；其余进入待确认。改期同事务取消旧待发提醒并建立新提醒。取消面试保留背景、音频、文字、报告。冷却期到期只提醒核验，不自动改为无限制。

准备页默认从实际申请带出材料；用户重新选择会新增背景版本。无申请可手动选已有版本，不反向伪造投递历史。M6尚未交付时不伪造改进建议；交付后读取其未完成项。

## 4. 状态和异常

- 无回复、未同步、授权失效分别显示；来源失效不改机会结论。
- 同账号重复消息不重复入库；不同账号相同消息编号不能合并。
- 模糊时间、缺时区、疑似同一邀请、冲突通知保留原文，先确认，不猜当前时间。
- 机器休眠时不承诺准时提醒；恢复后记录错过和待处理。关闭窗口后是否仍提醒必须实测后台。
- 自动邀请处理要有可追溯依据和修正入口，不覆盖用户后来明确修改的安排。

## 5. 验收

| 编号 | 场景 | 标准 |
|---|---|---|
| M4-A1 | 导入一条含岗位/时间的邀请及一条模糊邀请 | 前者给明确可核对建议，后者待确认；不乱关联 |
| M4-A2 | 两账号同编号、同账号重复、邀请改期/取消 | 身份不串；同一场更新；旧提醒取消；材料不删 |
| M4-A3 | 同步中断后恢复、来源失效、没有新消息 | 游标与数据一致；不丢/重消息，不误记拒绝 |
| M4-A4 | 无申请直接补录过去面试、缺JD/简历 | 可进入准备/记录；缺项可见，无虚假申请 |
| M4-A5 | 关闭窗口、休眠、恢复、用户确认提醒 | 实际送达/错过/确认有记录；不伪造准时送达 |
| M4-A6 | 旧申请后简历更新，再准备下一轮 | 当次背景版本明确；旧背景不改；未完成改进可读 |

测试位置：tests/test_interviews.py、test_workbench.py、test_http.py，新增反馈同步与日程页面测试；系统提醒在隔离环境验证。当前SaveInterview和AcknowledgeReminder服务代码可复用，但真实提醒、完整页面、反馈接入分别验收。

准入：负责人确定与用户实际沟通渠道相符的只读入口、权限和稳定身份；明确Windows时区数据部署及提醒方式。需要用户账号授权时提供具体渠道/权限/撤回方式，不让用户选择内部技术方案。未确定渠道时可推进已审M4a/M4b，不宣布M4整体完成。
