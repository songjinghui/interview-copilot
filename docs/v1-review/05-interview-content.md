# M5：取得可回看、可校对的面试内容

状态：草案 v1，待顺序审阅。返回[总览](README.md)；共用[data-flows](data-flows.md)。

## 1. 结果与边界

用户在一场面试下导入或主动录制音频；安全保存后自动本地转写，校对文字和角色，能回看对应音频。没有录音时可以记回忆并继续复盘。

音频本机保存和处理；模型首次下载与处理面试音频分开说明。自动后台转写、重启恢复和已验证的双侧录制场景都是本块验收项。有“转写任务已创建”而无实际文字产物不能算完成。

## 2. 功能拆分

| 子段 | 用户操作与结果 |
|---|---|
| M5a 内容入口与本地转写 | 上传已支持音频→保存即转写→文字；无音频可写回忆；明确格式/大小/模型状态 |
| M5b 校对与来源 | 音频回放、时间定位、说话人/术语修正、多个文件选择/组合、文字历史 |
| M5c 主动录制与恢复验收 | 设备测试、双方声音验证、主动开始/停止、片段保存、任务恢复与暂停控制 |

页面以该场面试现有文字/音频为主，无内容时展示录音、导入或写回忆入口。保存成功显示实际转写状态，不再要求点一次“开始转写”。普通任务后台执行不持续弹窗；需要补模型/找文件时才给行动入口。

## 3. 数据与运行交互

| 对象 | 字段/关系与规则 |
|---|---|
| 物理文件 | file_assets保存ready校验与相对路径；不直接信任用户输入路径；引用前验证文件身份 |
| 音频集合与片段 | audio_assets归属interview_id，origin/status/completeness；audio_parts关联文件与原时间区间 |
| 转写任务 | background_tasks + transcription_jobs固定音频revision、配置、请求代次及执行身份 |
| 文字版本 | transcript_versions区分asr/manual/correction/combined；每场多个不可变版本 |
| 段落 | transcript_segments保存段落键、角色、文字、来源音频/版本/原时间；ordinal仅表示阅读顺序 |

导入/StopRecording→文件落盘及校验→同事务发布音频与唯一任务→独立worker本地转写→核对执行身份后同事务发布文字/段落和成功结果。写事务不覆盖转写计算过程。

校对保存生成新版本；组合不同音频的两个00:30片段时，分别保留音频ID与原时间，不能拼出假的连续时间线。手工回忆只有段落依据，没有虚构时间码。

中断恢复沿用同一任务，允许引擎从头计算但不能重复发布结果；用户明确“重新转写”才增加代次。旧worker迟到、用户暂停/取消后迟到的结果均须受执行身份检查约束。原文字和用户校对不能被新结果覆盖。

## 4. 设备、失败和持久化

- 录制前展示来源、电平和短样本回放；用户主动开始并完成必要告知/授权。设备断开标记缺口，不在恢复时悄悄重开麦克风。
- 录音采集与普通网页生命周期分开；关页面仍录制时提供明确继续/停止选择。
- 模型缺失、文件缺失、空间不足、格式不支持都保留现有材料，给出具体恢复操作；无可靠进度不编百分比。
- 关窗、杀worker、服务重启、休眠恢复、登录恢复和用户主动停后台分别验证；暂停任务重启后仍暂停。
- 录制兼容范围在目标电脑实测后标注；不承诺所有设备/会议软件，未验证场景保留已有音频导入入口。

## 5. 验收

| 编号 | 场景 | 标准 |
|---|---|---|
| M5-A1 | 导入本机支持音频，模型已安装后断网 | 自动产出真实文字，可回看；没有云端音频请求 |
| M5-A2 | 有中文术语、多角色、重叠语音的代表性样本 | 人工核对可校对性；记录耗时/资源/错误，不编识别率 |
| M5-A3 | 服务/worker中断、休眠、主动暂停 | 自动恢复应恢复的任务；暂停保持；只发布一次结果 |
| M5-A4 | 多文件同时间码、组合后校对、重开应用 | 每个引用回到正确原文件与时间 |
| M5-A5 | 录制双方声音、设备断开、停止重复请求 | 双侧样本证据、缺口可见、保存和任务幂等 |
| M5-A6 | 无音频写回忆、重转写已有录音 | 来源明确；原记录/校对保留；M6能选择完整版本 |

测试位置：tests/test_audio_import.py、test_phase3_service_review.py、test_interviews.py，新增worker/文字版本/内容页面测试，真实设备与故障恢复记录。现有已登记WAV的服务流程可以复用；上传、真实引擎、设备采集不能用mock测试代替完成证明。

准入：负责人在目标电脑选择并实测本地ASR/采集方案、支持格式、下载体积与可接受等待；涉及新依赖/设备授权时列具体事项。M5a先提供可用结果，M5c仍保留首版承诺，不以“导入可用”悄悄取消录制和恢复。
